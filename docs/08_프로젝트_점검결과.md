# 프로젝트 점검 결과

점검일: 2026-09-09. 문서·소스·이미지·기존 PPT·로컬 DB·Microsoft 공식 자료를 확인했습니다.

**판정: 소규모 사내 포털에 사용할 기본 구조와 동작은 확인했지만, 현 환경을 그대로 정식 운영하기에는 해결할 항목이 있습니다.** 인원수가 적다고 라이선스·데이터 보안·복구 조건이 면제되지는 않습니다.

## 운영 전에 해결해야 하는 항목

| 우선순위 | 확인한 사실 | 조치 및 담당 |
|---|---|---|
| 높음 | 실제 워크스페이스 용량은 PP3 / Premium Per User - Reserved | Power BI 담당자가 지원 유료 용량을 준비·배정하고 재검증 |
| 높음 | 기존 최신 자동 백업 0바이트. 전체 DB 백업을 다시 실행해도 analytics 스키마 접근 권한 부족으로 실패 | DB 담당자가 전체 백업 계정 권한을 확인하고 유효 백업·별도 보관·격리 복원을 검증 |
| 민감 데이터이면 높음 | 18개 활성 보고서 중 13개에 브라우저 표시 필터가 설정됨. 이 필터는 우회 가능 | 제작자가 모델 RLS를 확인. 실제 일반 사용자별 기대 행과 금지 행을 비교 |
| 높음 | 로컬 COOKIE_SECURE=false. 실제 운영 HTTPS 경로는 이번에 확인하지 못함 | 서버 담당자가 HTTPS와 Secure 쿠키 적용 확인 |
| 사용량에 따라 | 1GB PBIX 전체 메모리 적재, 프로세스 내부 업로드 작업, 단일 worker의 백그라운드 루프 | 실제 동시 업로드·열람 부하 측정, 필요할 때 작업 처리 분리 |

Microsoft는 App-Owns-Data 운영에서 Pro·PPU 사용자 라이선스만으로 사용할 수 없다고 명시합니다. dedicated=true, 체험 배너가 없음, 토큰 발급 성공은 그 요건을 대신하지 않습니다. [Microsoft 라이선스 조건](https://learn.microsoft.com/en-us/power-bi/guidance/powerbi-implementation-planning-usage-scenario-embed-for-your-customers#licensing)

모델 RLS는 토큰의 EffectiveIdentity와 모델 역할로 적용합니다. 이번 표본 보고서는 역할을 요구하여 신원·역할을 포함한 토큰 발급에 성공했지만, 허용/금지 행 자체는 검증하지 못했습니다. [Embedded RLS](https://learn.microsoft.com/en-us/power-bi/developer/embedded/cloud-rls)

## 수정 완료

| 문제 | 변경 |
|---|---|
| 잘못되거나 만료된 Bearer를 다른 탭의 쿠키로 대체 | Authorization이 있으면 해당 토큰만 인증. 프론트의 무효 토큰을 지워 로그인 반복도 방지 |
| X-Forwarded-For를 앱이 무조건 신뢰 | Uvicorn이 확인한 request.client만 사용 |
| SSO 탭 토큰을 다음 HTTP 요청 URL에 포함 | URL fragment로 전달 후 sessionStorage에 옮기고 주소에서 제거 |
| 인증 응답·토큰 캐시 정책 및 기본 헤더 부족 | no-store, no-referrer, nosniff, 프레임 삽입 차단 헤더 추가 |
| bcrypt 5에서 72바이트 초과 입력이 예외 발생 | 로그인은 인증 실패, 계정 생성은 400으로 처리. 해시 연산은 스레드로 이동 |
| 관리자 권한 화면이 공용·소유자·개인 차단을 다르게 표시 | 실제 열람 SQL로 통일하고 허용 경로 표시 |
| JSON 문자열 false가 허용 true가 됨 | 권한 변경은 실제 boolean만 허용 |
| 삭제·비활성 보고서의 기존 캐시 토큰 재사용 가능 | 활성 보고서인지 캐시 조회 전에 확인 |
| 로컬 DB에 모델 참조가 없으면 의미 모델 자동 삭제 | 미등록 보고서·타일 참조를 보호하도록 모델 자동 삭제 제거 |
| 시작할 때 공용 보고서를 비공개로 변경하고 레거시 테이블·뷰·컬럼 삭제 | 초기화는 누락된 구조 추가만 수행. 기존 데이터·권한 보존 |
| 신규 DB에서 users.email 누락 | 초기화에 SSO 컬럼·유니크 인덱스 포함, 별도 중복 스크립트 삭제 |
| 최초 관리자 생성 경로 없음 | 비밀번호 비표시 입력을 사용하는 create_admin.py 추가. 기존 계정은 덮어쓰지 않음 |
| 백업 경로 고정·실패 시 0바이트 정상 확장자·수동 백업 자동 삭제 | 경로 설정 지원, 부분 파일 사용, 성공 후 이름 변경, 자동 백업 파일만 보존정책 적용 |
| README·관리자 기술 문서의 오래된 비용·권한·기능 설명 | 현재 코드와 공식 조건으로 재작성 |
| 일반 사용자 안내 없음 | 로그인 전후 접근할 수 있는 /help와 SVG 흐름도 추가 |

코드 변경은 작업 폴더에 반영했습니다. 운영 서버 재기동, 실제 계정·권한 변경, Power BI 게시·삭제, 용량 구매·배정은 실행하지 않았습니다.

## 파일 정리

총 **280개 파일, 30,123,869바이트(약 28.7 MiB)**를 삭제했습니다.

- 중복 PPT 초안 3개(v1~v3). 최신 v4 48장과 생성 원본은 보존했습니다.
- PPT 후보·검사·프리뷰·렌더링 중간 파일.
- 제거된 DB/RLS 구조와 잘못된 PPU 운영 설명이 남아 있던 옛 도면 HTML·PNG 2개. 현재 문서의 Mermaid와 신규 SVG로 대체했습니다.
- 캐시 설명 중복 문서를 DB/API 흐름 문서로 통합했습니다.
- 초기화에 합친 SSO 컬럼 스크립트와, 설명과 달리 부서 권한까지 연쇄 초기화하던 보고서 리셋 스크립트를 제거했습니다.
- 의미 모델 자동 삭제 제거로 미사용이 된 모델 삭제·참조수 헬퍼를 소스에서 정리했습니다.

.env, DB와 백업·로그, 실행 의존성, 외부 참고 이미지 defineview는 보존했습니다. PPT 빌드의 node_modules는 공유 런타임으로 연결된 junction이므로 삭제하지 않았습니다. 기존 .gitignore 사용자 변경도 유지했습니다.

공통 문서를 정리하면서 사내 계정·식별자·옛 접속 주소·예시 비밀번호를 제거하고 검토된 문서만 Git 추적 대상에 추가했습니다. 과거 커밋에 남은 값은 별도 이력 문제이며 이번 작업이 Git 이력을 제거하지는 않습니다. 예시 자격 증명을 실제로 재사용했는지는 확인하지 않았습니다.

## 추가로 알아둘 제한

- 포털 권한 회수·계정 비활성화는 다음 앱 요청부터 반영됩니다. 이미 발급된 임베드 토큰은 만료 전까지 쓸 수 있습니다.
- 포털 로그인도 서명된 세션/탭 토큰 방식입니다. 브라우저 로그아웃이 탈취된 토큰의 서버 측 즉시 폐기를 보장하지는 않습니다. 공유 PC에서는 계정별 브라우저 프로필 사용을 권합니다.
- SSO는 현재 이메일로 기존 포털 계정에 연결합니다. 계정 재할당·이메일 변경은 관리자가 매핑을 검토해야 합니다.
- 서버 시작 시 DB 연결이 필요하며 장애 시 고가용성·서비스 자동 재시작은 별도 운영 설정입니다.
- repo LICENSE는 독점 라이선스입니다. 외부 고객사 배포는 해당 사용권 계약과 타사 구성요소 고지를 별도로 확인해야 합니다. 이번 점검은 모든 계약·개인정보 처리 의무의 충족을 확인한 것은 아닙니다.
