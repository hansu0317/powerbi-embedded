# 보고서 권한, 부서 표시 필터, Power BI RLS

2026-09-09 기준. **표시 필터는 다른 부서의 데이터를 보호하지 않습니다.** 작은 회사에서도 급여·고객·원가 등 열람 범위가 다른 데이터라면 모델 보안을 별도로 설정해야 합니다.

| 구분 | 적용 위치 | 통제 대상 | 현재 구현 |
|---|---|---|---|
| 포털 열람 권한 | 서버 + PostgreSQL | 어떤 보고서를 열 수 있는가 | 공용·소유자·개인·부서 허용, 개인 차단 우선 |
| 부서 표시 필터 | 브라우저 Power BI SDK | 기본 화면에 어떤 행을 보여주는가 | reports.filter_table/filter_column + users.department |
| 모델 RLS | Power BI 의미 모델 | 사용자가 어떤 행을 조회할 수 있는가 | 모델이 요구하면 서버가 identity/roles를 토큰에 포함 |

## 표시 필터의 정확한 동작

관리자, 부서 미배정, 부서 값이 ALL인 사용자는 표시 필터를 적용하지 않습니다. 보고서의 테이블명·컬럼명이 둘 다 있을 때만 일반 사용자 부서값으로 필터를 만듭니다.

설정이 빠지면 필터가 생략됩니다. 이를 “안전한 실패”로 해석하면 안 됩니다. 필터가 있어도 브라우저 SDK로 바꾸거나 제거할 수 있습니다. 필터 창 숨김·잠금은 보안 기능이 아닙니다.

예시 설정은 보고서 제작자가 모델의 실제 이름을 확인한 뒤 적용합니다.

```sql
UPDATE reports
SET filter_table = 'DimOrg', filter_column = 'Department'
WHERE id = <대상 보고서 ID>;
```

## 민감 데이터용 모델 RLS

1. Power BI Desktop에서 모델의 보안 역할과 사용자별 허용 범위를 정의합니다. 이 앱은 공통 역할 이름 `PBI_RLS_ROLE_NAME`을 사용합니다.
2. 동적 RLS가 `USERNAME()` 등을 사용하는 경우, 토큰에 들어가는 `users.pbi_username`과 모델의 매핑 값이 일치하도록 설계합니다. 기본 계정 생성 시 포털 아이디가 이 값으로 들어갑니다.
3. 의미 모델과 보고서를 워크스페이스에 게시합니다. 서비스 주체에 보고서·모델 워크스페이스의 Member 또는 Admin 권한을 준비합니다.
4. 서버가 GenerateToken에 `username`, `roles`, `datasets`를 전달하는지 확인합니다. 모델이나 역할을 바꾸면 기존 토큰 캐시도 고려하여 재시작 또는 캐시 무효화 후 확인합니다.
5. **일반 사용자 두 명과 미등록 신원**으로 실제 임베드 화면을 검증합니다. 허용 행은 보이고, 타 부서·미등록 신원의 행은 보이지 않아야 합니다.
6. 화면 필터를 제거해도 금지된 행을 얻을 수 없는지 검증합니다. 실제 기대 행 집합과 비교해야 하며 단순히 두 화면이 다르다는 것만으로 충분하지 않습니다.

Microsoft는 App-Owns-Data에서 토큰의 EffectiveIdentity로 모델 보안을 적용하도록 안내합니다. 포털 관리자도 RLS 신원을 넘기면 그 신원의 모델 보안을 적용받습니다. 포털 관리자 여부가 Power BI RLS 자동 우회권이 되지는 않습니다. [Embedded RLS](https://learn.microsoft.com/en-us/power-bi/developer/embedded/cloud-rls), [임베디드 보안](https://learn.microsoft.com/en-us/power-bi/developer/embedded/embedded-row-level-security)

## 기존 모델의 데이터 새로고침

이전 문서에는 제거된 DB 뷰를 참조하는 모델의 새로고침 실패를 감수한다는 설명이 있었습니다. 이는 정상 운영 기준이 아닙니다. 화면이 떠도 오래된 Import 데이터일 수 있으므로 모델별 데이터 원본 자격 증명·게이트웨이·최근 새로고침 성공 여부를 확인해야 합니다. 기존 역할이나 모델 참조는 확인 없이 삭제하지 않습니다.

`scripts/check_rls_render.py`는 운영자 진단 도구이며 포털 권한 검사를 우회해 테스트 토큰을 발급합니다. 일반 사용자 배포용이 아니며 출력 HTML에는 임베드 토큰이 포함될 수 있습니다. 결과는 공유하지 않고 점검 후 삭제합니다.

“웹에 게시(Publish to web)”는 공개 배포 기능이므로 이 포털의 사내 권한·RLS 구성 대안으로 쓰지 않습니다.
