# Power BI 운영 용량과 라이선스

확인일: 2026-09-09. **PPU 계정 1개만으로 App-Owns-Data 운영 환경을 구성할 수 있다는 기존 설명은 정정합니다.**

## 실제 확인과 운영 조건

서비스 주체로 워크스페이스와 capacities API를 조회한 결과, isOnDedicatedCapacity=true이며 연결된 SKU는 PP3, 표시 이름은 Premium Per User - Reserved였습니다. 이 속성과 토큰 발급 성공은 운영 라이선스 충족의 증거가 아닙니다.

Microsoft는 App-Owns-Data 운영에 용량 기반 유료 상품이 필요하며 Free·Pro·PPU 사용자 라이선스만으로는 해당 운영 시나리오를 사용할 수 없다고 명시합니다. [운영 라이선스 조건](https://learn.microsoft.com/en-us/power-bi/guidance/powerbi-implementation-planning-usage-scenario-embed-for-your-customers#licensing)

| 구성 | 포털 직원 개인 Power BI 라이선스 | 이 프로젝트에서의 의미 |
|---|---|---|
| App-Owns-Data + 지원 유료 F/A 등의 용량 | 임베드 열람자에게 불필요 | 현재 인증 구조로 운영하려면 준비할 기반 |
| PPU/PP3만 존재 | 직원 라이선스 면제 운영 조건 충족으로 볼 수 없음 | 현재 조회된 구성. 운영 전 전환 필요 |
| Power BI 서비스 직접 열람 / User-Owns-Data | 별도 제품·용량 규칙에 따라 필요 | 현재 서비스 주체 방식과 다른 구성 |

기존 P/EM 용량의 가용성과 구매 조건은 계약에 따라 확인합니다. F64 기준 등 Power BI 서비스 직접 공유 규칙을 이 앱의 App-Owns-Data에 그대로 대입하지 않습니다. [Embedded 용량과 SKU](https://learn.microsoft.com/en-us/power-bi/developer/embedded/embedded-capacity)

## 작은 회사의 선택

### 운영 용량 없이도 지금까지 개발된 이유

서비스 주체의 인증·워크스페이스 권한이 갖춰져 있으면 API가 실제로 응답할 수 있습니다. 이번 환경에서도 PP3 배정 상태에서 일반 사용자 표본의 GenerateToken 호출이 성공했습니다. 이는 관찰된 기술적 동작이며 Microsoft가 해당 운영 구성을 승인했다는 뜻은 아닙니다. PP3에서 이 요청을 허용한 Microsoft 내부 판단 근거는 응답만으로 단정할 수 없습니다.

Microsoft는 개발 테스트용 임베딩과 운영 배포를 구분합니다. “개발 자체가 불가능하다”가 아니라 “PPU만으로 운영 라이선스 요건을 충족하지 못한다”가 정확한 표현입니다. [개발·운영 구분](https://learn.microsoft.com/en-us/power-bi/developer/embedded/embedded-capacity#capacity-considerations)

사내망·소규모·비공개 포털이라는 이유로 PPU 단독 운영을 면제하는 예외는 확인한 공식 조건에 없습니다. 직원이 실제 업무에 지속적으로 사용하는 것을 단순 개발 테스트라고 볼 근거도 없습니다. 즉시 차단되거나 언제 문제가 생길지까지 예측할 수는 없지만, 현재 동작을 근거로 적합한 운영 구성이라고 보장할 수는 없습니다.

회사 규모가 작아도 운영 용량 요건은 면제되지 않습니다. 현재 포털을 유지한다면 지원 용량을 준비해야 합니다. 직접 Power BI 공유로 바꾸려면 직원 계정·라이선스 비용과 포털 인증 구조 변경을 별도로 비교해야 합니다.

이번 점검에서는 SKU 구매나 워크스페이스 이동을 수행하지 않았습니다. 지역·계약·가동 시간·동시 사용량이 없어 비용 금액을 추정하지 않습니다. 최소 SKU가 실제 보고서의 모델 크기와 부하를 처리하는지도 검증해야 합니다.

## 재확인

```powershell
.\venv\Scripts\python.exe scripts/check_capacity.py
```

종료 코드: 0=지원 SKU 확인(유료·활성 상태와 렌더링은 별도), 2=PPU 등 비지원 또는 용량 없음, 3=권한·통신 때문에 확인 불가. capacity 목록이 비어 있으면 서비스 주체의 조회 권한 문제일 수 있으므로 미구매로 단정하지 않습니다.

SSO 성공은 포털 사용자 본인 확인이고, 서비스 주체 토큰 성공은 API 인증입니다. 둘 다 용량 이용권을 대신하지 않습니다.
