# 개발자 읽기 순서

2026-09-09 코드 기준입니다. 일반 사용자는 [열람 가이드](07_일반사용자_보고서열람가이드.md)를 먼저 봅니다.

1. `README.md`: 운영 전제, 실행 방법, 지원 범위를 확인합니다.
2. `main.py`: 라우터·세션·보안 헤더와 lifespan 작업을 확인합니다.
3. `deps.py` → `routes/auth.py` → `database/auth.py`: 포털 로그인·비활성 계정 차단·CSRF를 따라갑니다. Bearer가 있으면 그 토큰만 인증하며 잘못된 토큰을 쿠키로 대체하지 않습니다.
4. `frontend/src/main.tsx` → `lib/api.ts`: 탭 토큰은 sessionStorage에, API 인증은 Authorization 헤더에 있습니다. SSO 결과는 URL fragment에서 소비합니다.
5. `routes/report.py` → `database/reports.py`: 목록과 단건 열람의 공통 권한 판정을 확인합니다. 실제 조건에는 개인·부서 외에도 소유자·공용이 포함됩니다.
6. `services/powerbi.py`: 활성 보고서 확인, 사용자별 캐시, 데이터셋의 RLS 필요 여부, GenerateToken을 따라갑니다.
7. `routes/report_upload.py` → `database/uploads.py` → `services/fabric.py`: 업로드 예약·게시·DB 등록·재시작 복구를 확인합니다.
8. `tests/`: 실제 SQL 권한 조합과 인증·토큰·백업 실패 회귀 테스트를 실행합니다.

## 세 가지 신원

| 신원 | 역할 |
|---|---|
| 포털 사용자 | 앱 로그인과 보고서 권한의 대상 |
| Entra 서비스 주체 | 서버의 Power BI/Fabric API 호출 신원 |
| 보고서 제작·운영 담당자 | 게시, 데이터 원본, 워크스페이스·용량 관리 |

PPU 사용자 라이선스와 서비스 주체 인증 성공은 운영용 용량 요건을 대신하지 않습니다. [라이선스 가이드](05_라이선스_용량_비용가이드.md)

## 유지보수 규칙

SQL은 database 함수로 모으고, 임베드 토큰은 services의 캐시 경로를 사용합니다. 단, 현재 Import REST 호출은 업로드 라우트에 남아 있습니다. 계층 분리는 유지보수 방향이며 코드 전체가 완전히 따르고 있다고 가정하지 않습니다.

config.py 상수와 .env는 재시작 후 반영됩니다. app_config는 미사용입니다. 스키마 초기화는 추가 작업만 수행하며 기존 권한·레거시 테이블을 삭제하지 않습니다.
