# 서버 운영 가이드

## 시작과 상태

Windows는 `scripts/server.ps1 start|stop|restart|status`, Linux는 `bash scripts/server.sh start|stop|restart|status`를 사용합니다. 기본 포트는 8249이며 .env의 PORT로 변경합니다. 두 스크립트 모두 백그라운드 실행입니다.

`GET /health`가 200이어도 Power BI 용량, 토큰, 데이터 원본, RLS, 새로고침 상태까지 정상이라는 뜻은 아닙니다. 실제 일반 계정으로 보고서 열람을 확인하세요.

## 배포

1. 현재 DB와 .env를 안전하게 백업합니다.
2. `pip install -r requirements.txt`, 프론트 `npm ci` 후 `npm run build`.
3. init_schema.py로 부족한 컬럼·인덱스를 추가합니다. 기존 권한과 레거시 데이터는 보존됩니다.
4. 프로세스를 재시작합니다. 배포 중에는 동시 PBIX 게시 작업이 없는지 확인합니다.
5. /health, 로그인, 일반 사용자 권한, 실제 보고서 한 개를 확인합니다.

새 DB는 `python scripts/create_admin.py`로 최초 관리자 계정을 생성합니다. 입력한 비밀번호는 명령줄이나 로그에 출력하지 않습니다. 기존 관리자가 있으면 이 도구는 계정을 변경하지 않습니다.

## HTTPS와 접속 IP

운영 주소 앞에 HTTPS 리버스 프록시를 두고 COOKIE_SECURE=true를 설정합니다. 서버는 기본 보안 헤더와 인증 응답 no-store를 반환합니다. 프록시가 보낸 클라이언트 주소는 Uvicorn이 허용한 프록시에서만 신뢰하게 하고 `--forwarded-allow-ips`에 실제 프록시 IP만 지정합니다. 앱 포트 직접 접근은 회사 네트워크 정책으로 제한합니다.

Microsoft 로그인·Power BI REST·Fabric REST 및 브라우저 보고서 렌더링 도메인의 HTTPS 통신이 필요합니다. 실제 방화벽 목록은 [Microsoft Power BI URL 목록](https://learn.microsoft.com/en-us/fabric/security/power-bi-allow-list-urls)과 회사 정책으로 관리합니다.

## 백업과 복원

자동 백업은 서버 로컬 시간 기준 평일 17시대에만 실행됩니다. 서버가 꺼져 있으면 실행되지 않으며 별도 스케줄러가 아닙니다. PG_DUMP_PATH 환경값, PATH, 기존 Windows 설치 경로 순으로 pg_dump를 찾습니다.

덤프는 .partial 파일에 쓰고 성공·비어 있지 않음을 확인한 후 .dump로 바꿉니다. 실패 파일은 완성 백업으로 남기지 않습니다. 30일 자동 보존정책은 시간 형식으로 생성한 자동 백업에만 적용하며 수동 작업 전 백업은 보존합니다.

**2026-09-09 확인한 기존 최신 자동 백업은 0바이트였습니다.** 파일 이름이나 로그만으로 복구 가능하다고 판단하지 마세요. pg_dump 성공과 pg_restore 목록 검사, 격리 DB 실제 복원, 권한·보고서 건수 대조까지 확인해야 합니다. 백업은 원본 서버와 다른 위치에도 보관합니다.

전체 DB 덤프에 실패하는 스키마가 있으면 해당 스키마의 소유권·백업 계정 권한을 확인합니다. 임의로 스키마를 제외하여 전체 백업이라고 부르지 않습니다.

```text
pg_restore --list <backup.dump>
createdb <별도 복원용 DB>
pg_restore --no-owner -d <별도 복원용 DB> <backup.dump>
```

운영 DB를 대상으로 복원하지 않습니다. 복원용 계정 권한과 확장·원본 역할의 호환성도 확인합니다.

## 장애 시

| 증상 | 확인 |
|---|---|
| 로그인 실패 | 활성 계정, 비밀번호, 15분 차단, SSO 이메일 연결 |
| 보고서 403 | 개인 차단, 개인/부서 허용, 공용 범위 |
| 임베드 5xx | Entra 자격 증명, 서비스 주체 허용·워크스페이스 권한, 모델 RLS, 용량 |
| 오래된 데이터 | 의미 모델 최근 새로고침, 원본 자격 증명, 게이트웨이 |
| 게시 중단 | upload_jobs 상태, import_id, Power BI 실제 게시 결과 |
| 백업 실패 | pg_dump 경로·버전, 저장 공간, DB 전체 스키마 권한 |

단일 worker 기준이며 worker를 늘리면 동기화·백업 루프가 중복됩니다. 다중 worker 전환은 작업 분리가 선행돼야 합니다. 서버 자동 재시작·외부 모니터링·부하 수치는 아직 이 점검으로 검증하지 않았습니다.
